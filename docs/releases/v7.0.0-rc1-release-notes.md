# Release Notes: Abast-gp V7.0.0-RC1

**Status:** Release Candidate 1
**Date:** 2026-08-09
**Target:** Production VPC (Cutover)

## 1. Engine States & Cutover Strategy
Se han implementado los estados finales de ruteo para el *Vector Engine Router*.
El proceso de Cutover (*Go-Live*) seguirá esta secuencia estricta:
1. `DUAL_READ` (Estado Beta previo).
2. `PGVECTOR_PRIMARY_SYNC`: Las lecturas primarias pasan oficialmente a **pgvector**. FAISS recibe escrituras síncronas en paralelo (Dual Write) para mantener paridad de datos garantizada. Si PostgreSQL sufre una caída transitoria, el sistema responde usando FAISS y si el umbral cruza el 5%, aplica Rollback a `FAISS_ONLY`.
3. `FAISS_STANDBY`: Tras 7 días de estabilidad confirmada en `PGVECTOR_PRIMARY_SYNC`, el sistema transiciona a *Standby*. FAISS deja de recibir escrituras y lecturas. Se convierte en un archivo histórico/Cold Standby. En este punto, un Rollback a FAISS requerirá una resincronización explícita (Resync).

## 2. Database Readiness & HNSW Sizing
Para escalar el índice HNSW en Producción (PostgreSQL 15+):
- **RAM (Shared Buffers):** Configurar al menos el 50% de la RAM del host para `shared_buffers` para garantizar que el índice HNSW completo resida en memoria (Hot Cache).
- **HNSW Parameters:** 
  - `m = 16` (Max connections per layer, balance ideal entre precisión y tamaño de índice).
  - `ef_construction = 64` (Memoria de construcción).
- **Crecimiento Estimado:** 1 millón de vectores de 1536 dimensiones requerirán ~7.5 GB de almacenamiento, más ~1.2 GB de overhead para HNSW. Aprovisionar discos EBS de alto IOPS.

## 3. High Availability (HA) Strategy
- **Replicación:** PostgreSQL se configurará en un esquema Multi-AZ con al menos una réplica Read-Only síncrona.
- **Recuperación:** Si el primario falla, el failover lógico apuntará el *Vector Service* a la réplica en < 30 segundos. Durante este período, el Gateway de Capa 7 cortocircuitará los Timeouts usando `FAISS_ONLY` (si se está en Primary Sync) sin alertar al usuario.

## 4. Backup & Security
- **Backup:** Extracciones WAL diarias a S3 (`pgBackRest`), con point-in-time recovery habilitado.
- **Seguridad:** Los vectores aislados bajo *Tenant ID* en JWT continúan operando con políticas RLS obligatorias. No hubo modificaciones que ablanden las restricciones implementadas en Alpha.
