# V6.1 FAISS Retirement Final Plan

**Date:** 2026-08-09
**Status:** PENDING SOAK (Waiting 30-day stability)

## 1. Contexto
V7.0.0 (pgvector) ha alcanzado la operación al 100% (Wave 5). De acuerdo a nuestras políticas de infraestructura, el sistema V6.1 heredado (FAISS + Vector Search Engine Legacy) debe ser retirado para optimizar costos de Nube (EC2/RAM) y reducir la superficie de ataque.

## 2. Criterios de Acción (Gates)
El retiro físico (apagado) **NO OCURRIRÁ HOY**. Se somete al siguiente período de cuarentena:
1. **Días 0 a 30:** Monitoreo activo de V7 al 100%. Los pods de FAISS permanecen vivos pero inactivos (solo consumiendo RAM, sin CPU).
2. **Día 30 (Aprobación SRE):** Si no hay *Emergency Rollbacks* registrados en este período.
3. **Día 31 (Cold Backup):** Se ejecuta el *Golden Backup*. Archivos `.faiss` crudos, metadata RocksDB y snapshots de EBS son empaquetados en un *Tarball* cifrado y subidos a AWS S3 Glacier Deep Archive (1 año de retención legal).

## 3. Ejecución del Retiro (Día 35)
Una vez validados los backups:
- **Kubernetes:** `kubectl scale deploy/faiss-search-engine --replicas=0`.
- **Gateway:** El código del `MigrationRouter` que gestiona estados (`DUAL_WRITE`, `FAISS_ONLY`) se marcará como *Deprecated* para ser removido en la v7.1.0 (Code Cleanup).

## 4. Auditoría
Cualquier reactivación de FAISS después del *Golden Backup* requerirá un procedimiento mayor de *Disaster Recovery* desde Glacier (SLA ~12 horas).
