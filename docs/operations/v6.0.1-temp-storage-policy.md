# V6.0.1 Temp Storage Policy

## 1. Propósito
Garantizar que la ejecución local del `DocumentQualityAssistant` (que opera descomprimiendo PDFs y analizando imágenes en OpenCV/Tesseract) no sature el disco duro local de los contenedores Docker ni genere vulnerabilidades por retención de datos.

## 2. Directorio Temporal (`/tmp/abast_uploads`)
Todo documento ingresado vía UI se almacenará de manera efímera en `/tmp/abast_uploads` dentro del contenedor de la API.

## 3. Límites Transaccionales
- **Tamaño máximo de PDF admitido en RAM**: 50MB (Archivos superiores deben ser subidos de forma paginada o dividida).
- **Tiempo máximo de retención (TTL)**: 5 Minutos.

## 4. Política de Eliminación Automática
- **Escenario A (QUALITY_BLOCKED)**: El script Python llamará a `os.remove(temp_path)` instantáneamente antes de devolver el error HTTP 400.
- **Escenario B (GOOD/WARNING/EXCEPTION)**: El archivo se moverá a `/storage/documents` (persistencia MinIO/Local) y se borrará del `/tmp`.
- **Escenario C (Crash/Timeout)**: Un _cronjob_ en el contenedor API ejecutará `find /tmp/abast_uploads -type f -mmin +5 -delete` cada 10 minutos para barrer residuos huérfanos.

No se conserva historial de imágenes degradadas en el servidor, solo el AuditLog (JSON).
