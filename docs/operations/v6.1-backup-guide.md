# Abast-gp V6.1 - Backup & Restore Guide

## 1. Política de Backup
Dado que V6.1 retiene la arquitectura transaccional PostgreSQL de V5.5, todos los expedientes, configuraciones de Tenant (`TenantConfiguration`), historial (`TenantConfigurationHistory`) y el `AuditLog` residen en la misma base de datos.

## 2. Ejecutar Backup (pg_dump)
Correr diariamente a las 02:00 AM mediante cron externo del Host:
```bash
docker exec -t abastgp_db_1 pg_dump -U $DB_USER abastgp -F c > /backups/abastgp_$(date +%Y%m%d).dump
```

## 3. Restauración (Disaster Recovery)
Si el contenedor PostgreSQL colapsa perdiendo su volumen:
1. Apagar todo: `docker-compose stop`
2. Levantar BD virgen: `docker-compose up -d db`
3. Restaurar:
```bash
docker exec -i abastgp_db_1 pg_restore -U $DB_USER -d abastgp < /backups/abastgp_YYYYMMDD.dump
```
4. Levantar resto del stack: `docker-compose up -d`
El historial de Configuración (RAG Thresholds) y el estado de Privacidad (Opt-In) se restaurarán automáticamente.
